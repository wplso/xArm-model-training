# 다음 세션 인계 · 새 볼트 고정 하중 캠페인

이번 세션에서 기존 볼트 자료로 4클래스 로지스틱 회귀를 적합했고, 다음 평가에 쓸 모델 세 개를 동결했다. 다음 세션의 첫 단계는 동결 모델과 현장 준비를 확인한 뒤, 새 캠페인 이름으로 정상·A·B·C를 수집하는 것이다.

## 동결한 모델

| 모델 | 학습 자료 | 경보 경계 |
|---|---|---:|
| V4 PCA-Q | 기존 볼트 고정 정상 200회 | 0.07929062136548198 |
| 몬스터겔 학습 4클래스 로지스틱 | 기존 몬스터겔 정상 70회와 A/B/C 40·50·40회 | 0.4915769243270105 |
| 볼트 학습 4클래스 로지스틱 | 11월 6일 볼트 G1 짝 정상 50회와 A/B/C 각 30회 | 0.8643103045703382 |

기존 두 모델은 원본과 바이트가 같은 사본을 저장했다. 새 볼트 모델은 기존 로지스틱과 같은 24개 특징·순서·분류기 설정을 사용했다. 대치·표준화기는 새 학습 140회만으로 적합했다. 짝 없는 G1 정상 17+13회는 이번 모델의 학습·교정·평가에 사용하지 않았다. 새 경계는 기존 두 모델과 같은 G0 정상 100회의 95백분위수(`higher`)다. 세 모델 모두 같은 교정 정상 100회에서 엄격한 `score > threshold` 기준으로 4회가 경계를 넘었다. 이는 교정 확인이며 새 세션 성능은 아직 측정되지 않았다.

볼트 G0와 G1 사이에는 MCU 시각과 센서 순번의 연속성이 끊겼다. 적합·교정 회차와 캡처 UUID, 캠페인이 겹치지 않음을 확인했다. [기존 그룹 목록](../../v5.1/GROUP_MANIFEST.csv) · [동결 명세](FROZEN_MODELS.json) · [학습·교정 목록](FIT_CAL_MANIFEST.csv) · [동결 검증](FREEZE_VERIFICATION.json)

## 새 캠페인 수집 순서

각 하중 직전에 **새 41g 정상 대조를 30회씩** 두는 계획이다. 하중별 탐지와 짝 정상 오탐의 분모를 동일하게 맞춘다. 총 180회이며 기존 회차당 약 22초를 적용하면 순수 반복은 약 66분이다. 장착 교체와 검증 시간은 별도다.

| 단계 | 조건 | 목표 |
|---|---|---:|
| N_A | 41g 운반, 상·하부 프레임 추가 하중 없음 | 30회 |
| A | 121g 운반, 프레임 추가 하중 없음 | 30회 |
| N_B | 41g 운반, 상·하부 프레임 추가 하중 없음 | 30회 |
| B | 41g 운반, 상부 프레임 총 +82g, 하부 하중 없음 | 30회 |
| N_C | 41g 운반, 상·하부 프레임 추가 하중 없음 | 30회 |
| C | 41g 운반, 하부 프레임 총 +182g, 상부 하중 없음 | 30회 |

1. 세 모델과 특징 추출기 해시를 `--verify-only`로 확인한다. 새 캠페인 ID를 정하고, 단계마다 신규 캡처 UUID와 전용 출력 폴더를 만든다. 실제 날짜·시각, 전원·휴지·직전 동작 이력, 시작 자세, 센서 고정 위치·방향, 물체와 프레임 질량을 기록한다.
2. 현장에서 로봇 정지, 41g 블록의 A 위치, 상·하부 추가 하중 없음, 베이스와 ADXL #1 고정, 배선·이동 경로, 현장 감시·ON/OFF 접근을 확인한다. 첫 회부터 검증된 원복 종료 자세 `A_release`를 목표로 한다. 시작 자세가 다르면 실제 자세와 준비를 기록하고 기존 자세 검사를 적용한다.
3. 기존 No.3와 B→A 자동 원복을 사용한다. 이전 수집기에서 검증한 자세·종료·통신·센서 감시 규칙, 원복 전 300ms 유예, 원복 중 위치 조회 제외를 재사용한다. 과거 수집기에는 이전 날짜·경로·승인 내용이 들어 있다. 다음 세션에서 **새 캠페인용 실행 설정과 출력 경로**를 만든 뒤 오프라인으로 점검한다. 첫 실기와 각 물리 조건 전환은 그때 준비와 감시 범위를 확인한 뒤 진행한다.
4. 단계마다 실제 운반·원복·정지 관찰과 원시 UART/HID·CSV·백업 감사 기록을 남긴다. 이상이 생기면 기존 중단 절차를 따르고 해당 회차와 원인을 보존한다. 품질 제외와 실제 라벨은 모델 점수를 보기 전에 확정한다. 시작 회차와 높은 모델 점수는 제외 사유로 사용하지 않는다.
5. 품질 검토를 마친 뒤 원시 `source`와 No.3 시간창을 [평가 목록 양식](EVALUATION_MANIFEST_TEMPLATE.csv)에 기록한다. `quality_valid=true`, `role=evaluation`과 실제 `label`·`pair_condition`을 붙인다. `source`는 센서·서보 CSV와 같은 캡처의 `manifest.json` 및 완료 이벤트가 들어 있는 실제 수집 폴더다. 원시 메타데이터에는 기존 조건과 같은 `rigid_fixed_operator_reported`, `bolt_and_nut_user_reported`, `evaluation_only` 및 실제 질량·부착 위치·자동 원복을 기록한다. 같은 캠페인의 여섯 단계는 독립 날짜 여섯 개로 해석하지 않는다.

과거 A/B/C 수집 색인(`hardware/No3_bolt_ABC_validation_20261106/EXPERIMENT_INDEX.json`)은 검증된 개별 수집기와 원시 감사의 위치를 찾는 용도다. [새 수집 계획](CAPTURE_PLAN.json) · [평가 정책](PROTOCOL.json)

## 수집 후 고정 평가

세 모델에 같은 유효 회차를 넣고 정상 전체·각 직전 정상의 FP와 분모, A/B/C의 TP와 분모, 짝 정상 AUROC·AP를 비교한다. 로지스틱 두 모델은 경보와 정확한 유형 분류를 구분한다. 같은 회차에서 몬스터겔 모델 대비 볼트 모델의 해소·신규 오탐과 추가·소실 탐지를 집계한다. 전체 정상 오탐이 늘지 않고 세 하중 탐지를 모두 유지하면서 적어도 한 항목이 개선되면 이번 캠페인에서 우세한 관측으로 기록한다. 짝 정상별 오탐이 악화되면 함께 표시한다.

새 회차는 평가 전용으로 유지한다. 두 모델은 장착 외에 학습 캠페인과 회차 수도 다르므로, 볼트 모델의 성능이 달라져도 장착 효과만 분리한 결과로 해석할 수 없다.

```powershell
$project = (Get-Location).Path
$study = Join-Path $project 'hardware\xarm_model_versions\bolt_known_load_prospective_20261111'
$py = Join-Path $project '.venv\Scripts\python.exe'
& $py -B -X utf8 "$study\evaluate_frozen.py" --project $project --verify-only
# 새 수집·라벨 확인·원시 감사 뒤에만 실행. 아래 경로를 새 실제 파일과 새 폴더로 바꾼다.
& $py -B -X utf8 "$study\evaluate_frozen.py" --project $project --manifest 'new_reviewed_cycles.csv' --output 'new_frozen_evaluation'
```

이번 세션의 신규 수집·신규 평가 회차는 0개다. 현장 상태와 다음 실행 범위는 다음 세션에서 확인한다.
